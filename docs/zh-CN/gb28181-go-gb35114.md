# GB 35114-2017 A 级安全（国密）：设备侧与平台侧双角色

[GB 35114-2017《公共安全视频监控联网信息安全技术要求》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=B7F5589329EF98B32F0EB8ACEC341C81)
在 GB/T 28181 的信令之上叠加了一层国密安全：SM2 证书双向认证、SM3
信令完整性、SM4 会话密钥协商。政企与等保场景的选型文档里，"GB35114 /
A级 / 国密 / SM2·SM3·SM4" 是硬关键词——**公开的开源实现里，同时覆盖
设备侧与平台侧 A 级握手的极少**，多数实现止步于摘要认证，或只做了单侧。
gb28181-go 把两侧都做齐了，且都是可选装配：不开 `gb35114` 构建标签时，
默认构建零国密依赖。

本文是专题手册：握手线格式、两侧接线、可配置的二义性、运维注意项。
快速上手见 [README](../../README.md#gb35114-a-level-security-v040-device--v050-platform-opt-in)。

## 只实现 A 级，是刻意的

GB 35114 分 A/B/C 三级：B/C 级额外要求信令安全 + **SVAC（GB/T 25724）
加密音视频**，而 SVAC 是硬件编解码器生态——纯软件开源库做不了，做了也
没有对端。因此本库明确只实现 A 级（`security35114` 包文档同样声明），
B/C 不在路线图上。A 级的覆盖面：

| A 级能力 | 本库落点 |
|---|---|
| SM2 证书认证（设备 → 平台） | 设备侧 `Authenticator`，替换 REGISTER 的 Digest 认证 |
| 平台身份认证（平台 → 设备，`Bidirection`） | 设备侧验 `sign2`；平台侧 `Platform` 签发 |
| 会话密钥协商（VKEK，SM2 信封下发） | 双侧，DER C1‖C3‖C2 信封 |
| 后续信令完整性（keyed-SM3 `Note` 头） | 双侧：设备签名外发，平台验证；v0.7.0 起平台下行请求设备侧也验 |
| SM4 流加密能力通告 | `A:SM2;H:SM3;S:SM4/OFB/PKCS5;SI:SM3-SM2` |

## 握手线格式（双方对同一张图）

```
REGISTER   (Authorization: Capability …, cnonce?)     设备 → 平台
401        (WWW-Authenticate: … random1="…")          平台 → 设备   Challenge
REGISTER   (Authorization: Unidirection|Bidirection
            … sign1="…")                              设备 → 平台   VerifyRegister
200 OK     (SecurityInfo: cryptkey [, sign2])         平台 → 设备
```

- `sign1` = SM2 签名（random2‖random1‖serverID，设备私钥）——证明设备持有
  FDWSF 证书对应的私钥；
- `cryptkey` = SM2 加密的 VKEK 信封（对设备证书公钥加密）——只有真设备能
  解开，之后每条请求的 `Note: Digest nonce="…",algorithm=SM3` 用它做
  keyed-SM3；
- `sign2`（仅 `Bidirection`）= 平台私钥对同一批随机数的签名——设备据此
  确认平台不是中间人。

握手之后：设备侧每个外发请求（keepalive、消息应答……）自动带 `Note`；
平台侧逐条验证。`RandomEncoding`、`Sign2Order`、`VKEKEncoding` 三个旋钮
对应标准文本与真实抓包之间的三处二义性，默认值取自实抓线格式
（`RandomEncoding`）与标准文本（`Sign2Order`）——联调遇到各家实现读法
不同时，先拨这三个旋钮，不要改代码。

## 设备侧接线（UAC）

```go
// go build -tags gb35114
import sec "github.com/mickeyzzc/gb28181-go/security35114"

auth, err := sec.New(sec.Options{
    Device:       devIdentity,     // sec.LoadIdentityFromFiles(certPEM, keyPEM)
    PlatformCert: platCert,        // sec.LoadCertificate(certPEM) — 验 sign2 用
    DeviceID:     "34020000001320000001",
    ServerID:     "34020000002000000001",
})
cfg.RegisterAuthenticator = auth   // 装上后 REGISTER 生命周期整体切换到 35114
```

装上 `RegisterAuthenticator` 后，REGISTER 的 Digest 舞步被完整替换为
Capability → 401 → sign1 → SecurityInfo；后续 keepalive 等请求自动带
`Note`。下行方向（平台 → 设备的请求带 `Note`）由
`device.Config.IncomingNotePolicy` 控制：默认 `Reject`（验签失败回 403），
灰度期可设 `Warn`（记日志放行）或 `Off`；不带 `Note` 的请求始终放行——
国密平台与 Digest 平台混跑时互不干扰。`Date` 头新鲜度窗为 ±5 分钟。

## 平台侧接线（UAS）

```go
// go build -tags gb35114
plat35114, err := sec.NewPlatform(sec.PlatformConfig{
    ServerID:    "34020000002000000001",
    Identity:    platIdentity,   // 平台 SM2 签名证书+私钥 — 签 sign2
    DeviceCerts: map[string]*smx509.Certificate{deviceID: devCert},
})
sipCfg.RegisterAuthenticator = plat35114 // platform/sip.Config；Digest 路径不动
```

`platform/sip` 按 REGISTER 的 Authorization 方案分流：`Digest` 走原有
摘要认证，`Capability/Unidirection/Bidirection` 交给 `security35114.Platform`，
200 OK 上附 `SecurityInfo`。两种认证的设备可以同时注册在同一平台。

平台侧的运维属性（多设备并发场景靠这些）：

- **按设备 ID 键控会话**，并发安全；
- **重放拒绝**——Authorization 回带的 `random1` 与挂起挑战不符即拒
  （`ErrChallengeMismatch`），映射 4xx；
- **重传幂等**——SIP-over-UDP 重传的 REGISTER 得到缓存的同一应答；
- **VKEK 灰度**——设备重新注册时，旧 VKEK 在校验位上保留到新握手完成，
  在线的 `Note` 不掉线；
- **证书来源两选**——`DeviceCerts` 预配，或信任 Capability `cnonce`
  自报证书（首连即收的选型，配合带外指纹核对使用）。

## 证书供给

GB 35114 的证书体系（FDWSF 前端设备证书、平台证书、CA 链）在标准里是
带外流程，本库不做证书签发/吊销。两个接入口：

- 带外预配（推荐）：设备证书灌进平台 `DeviceCerts`，平台证书灌进设备
  `Options.PlatformCert`；
- `cnonce` 自报：设备 `Options.IncludeDeviceCert = true` 在 Capability
  里带上证书 PEM，适合证书无法预灌的联调场景——**生产环境务必配合
  指纹核对**，否则自报通道等价于无认证。

## 构建与依赖

```sh
go build -tags gb35114 ./...
```

SM2/SM3 来自 [emmansun/gmsm](https://github.com/emmansun/gmsm)（纯 Go，
GM/T 0015-2012 SM2 X.509 证书）——仅 `gb35114` 标签构建时引入，默认构建
不携带该依赖。CI 对带标签构建同样跑测试。

## 验证方式（不是"写了应该能用"）

- **golden 线格式**：三个认证头（Authorization/WWW-Authenticate/
  SecurityInfo）与 `Note` 的逐字节钉板测试；
- **端到端 loopback**：真 `device.Server`（装设备侧 Authenticator）
  对真 `platform/sip.Server`（装 `Platform`）——握手、VKEK 协商、
  首条 keepalive 的 `Note` 验证全在真 SM2/SM3 下完成；
- **下行验证**：带 `Note` 的平台请求在设备侧的接受/拒绝矩阵有独立测试。

## 选型速查

- 要"视频联网 + 国密合规"（等保、政企内网）：本库 A 级双角色 + GB/T
  28181-2011/2016/2022 信令，同一套库。
- 对端是 GB35114 平台/设备：本库可直接互认；联调异常先查本文三个旋钮。
- 需要 B/C 级（SVAC 媒体加密）：超出本库范围，需要硬件 SVAC 生态。
- 只需要传输安全不需要 35114：用 SIPS（TLS 信令，`-transport tls`，
  见 [互操作教程](gb28181-go-interop-lab.md)）即可，不必上国密。
